# Design: reconcile-speckit-uf-refs

## Context

The five upstream speckit command templates lack UF references
(Dewey, `.specify/memory/constitution.md`, and — implement-only —
`/uf.review-council`). ADR-002 pinned the durable injection layer
as **Step 6 of `uf.init.md`** because the `speckit.*.md` files are
non-embedded and regenerated by `specify init` + `/uf.init`
(`knownNonEmbeddedFiles`, `scaffold_test.go:1242-1251`). A
red-first regression test (`TestSpeckitTemplates_RequiredReferences`,
issue #548) already encodes the required-reference matrix and fails
RED. This change (issue #549) is the reconciliation edit that turns
it green.

## Goals / Non-Goals

### Goals
- Inject the ADR-002 / D4 required-reference matrix into the three
  existing Step 6 guardrail blocks of `uf.init.md`.
- Keep the canonical source and embedded asset byte-identical.
- Turn `TestSpeckitTemplates_RequiredReferences` green while
  keeping `TestEmbeddedAssets_MatchSource` and
  `TestGuardrailTemplates_CommandSpecificContent` green.

### Non-Goals
- Editing the standalone `speckit.*.md` files directly (rejected
  by ADR-002 — non-durable).
- Restructuring Step 6 into per-file blocks (not required; the
  test is forward-compatible with the shared spec-phase block).
- Adding new commands, dependencies, or runtime behavior.
- Modifying any gatekeeping value (thresholds, severity, CI flags).

## Decisions

**D1 — Edit target: Step 6 of `uf.init.md`.** Authoritative per
ADR-002 Option B. The test reads
`assetContent("opencode/commands/uf.init.md")` and scopes to the
region between `### Step 6:` and `### Step 7:`.

**D2 — Scope: exactly the five in-scope upstream files.** Enumerated
explicitly (specify, plan, tasks, implement, constitution). The
four UF-custom commands (analyze, checklist, clarify,
taskstoissues) and testreview are excluded.

**D3 — No per-file restructuring.** The gating test keys on three
existing block labels (`Spec-phase guardrails block`, `Implement
guardrails block`, `Constitution guardrails block`); the shared
spec-phase block covers specify/plan/tasks and the test names the
exact file on failure. Injection into existing fenced blocks is
sufficient.

**D4 — Required-reference matrix.** Dewey (`dewey_semantic_search`
OR `dewey_search`) + `.specify/memory/constitution.md` for all
three blocks; `/uf.review-council` in the Implement block only.
The implement-only boundary is enforced by
`TestGuardrailTemplates_CommandSpecificContent` mustNotContain
assertions — do not leak `/uf.review-council` into the other
blocks.

**D5 — Co-merge with #548 on one branch.** The test (#548) and this
fix (#549) MUST land in the same PR to avoid a red `main` window.
Implemented on `opsx/add-speckit-ref-assertion-test`. The two
remain separate issues; the PR description states the co-merge
rationale to pre-empt scope-creep objections in review.

**D6 — Lockstep dual-write.** Edit `.opencode/commands/uf.init.md`
and mirror byte-for-byte into
`internal/scaffold/assets/opencode/commands/uf.init.md`;
`TestEmbeddedAssets_MatchSource` enforces identity.

## Risks / Trade-offs

- **Phase-boundary leak (MEDIUM).** Accidentally adding
  `/uf.review-council` to the spec-phase or constitution block
  ships a phase-boundary violation to every downstream `uf init`.
  Mitigated by the mustNotContain assertions in
  `TestGuardrailTemplates_CommandSpecificContent`.
- **Drift between copies (LOW).** Editing one copy but not the
  other. Mitigated by `TestEmbeddedAssets_MatchSource` (and its
  reverse-drift check).
- **User-facing blast radius (LOW, accepted).** Step 6 runs during
  `uf init` and ships via the embedded binary; a malformed block
  edit would change downstream injection. Mitigated by the three
  guarding tests run with `-race -count=1` before merge.
- **Red-main window if merged separately (avoided).** Addressed by
  D5 co-merge on a single branch/PR.
